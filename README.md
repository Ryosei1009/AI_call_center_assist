# コールセンター リアルタイム業務支援デモ

コールセンターのオペレーターを助けるデモです。通話の声をその場で文字にし、お客様の質問への回答候補を出したり、通話の記録をフォームに自動で入れたりします。

演習課題3で提案したシステムを形にしたものです。商品、FAQ、マニュアルのページ番号はすべて架空です。実際の通話やマニュアルは使わないでください。

仕組みと授業との関係は、知識がない人にも分かるように [docs/システム解説.md](docs/システム解説.md)（[PDF](docs/システム解説.pdf)）で説明しています。

## できること

- **文字起こし**：マイクの声を、話の切れ目ごとに文字にします。
- **回答候補の表示**：お客様の質問を見つけると、マニュアルから回答候補を最大3件、出典（マニュアルのページ）と一緒に出します。自信が低いときは「候補なし」と出します。
- **フォームの自動入力**：会話から「用件」「対象商品」「結果」を取り出してフォームに入れます。「やっぱりやめます」のように話が変わると、あとの内容で上書きします。
- **登録**：オペレーターがフォームを確かめて登録すると、`output/registered_calls.csv` に保存します。
- **録音で発表**：事前に録った音声を流して、聞き間違いや周りの雑音を気にせず発表できます。

扱う商品は、食材3つ（瀬戸内海鮮セット、讃岐うどんセット、和牛すき焼きセット）と保険2つ（みらい入院プラン、やすらぎがんプラン）です。

## 準備

Python 3.13 で専用の仮想環境を作ります。Python 3.14 では PyAudio の配布版がなく、インストールに失敗します。

```powershell
cd AI_call_center_assist
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

## 実行

```powershell
python main.py
```

初めて「通話開始」を押したときに、文字起こしのモデル（small、約500MB）をダウンロードします。2回目からは不要です。

## 使い方

1. 「通話開始」を押し、最初の1秒は静かにします（周りの雑音の大きさを測ります）。
2. 話す人を「お客様」か「オペレーター」に切り替えて話し、0.6秒ほど間を空けます。
   話さない間や、周りがうるさいときは「ミュート」（Ctrl+M）を押すと、その間の音声を無視します。
3. 回答候補を確かめ、回答に使ったら「この回答を使った」を押します。
4. フォームを確かめて、「確認して登録」を押します。

マイクがなくても「文字で試す」で動きを確かめられます。

### 録音で発表する

1. 台本（`data/demo_script.json`）に沿って録音します。Enter で開始・停止し、再生して確かめられます。

   ```powershell
   python record_demo.py      # 全部録音する
   python record_demo.py 3    # 3番だけ録り直す
   ```

   音声は `demo_audio/` に `01_customer.wav` のような名前で保存します。名前の `customer`／`operator` で話す人が決まります。
2. `python main.py` で起動し、「録音で発表」を押します。
3. 「▶ 次の発話」（F5）を押すたびに、1つの発話をスピーカーで流してから文字にします。画面の下に、次に流す文と見せどころが出ます。
4. 5番目で自動的に新しい通話になります。「この回答を使った」「確認して登録」は手で押します。

画面は最大化して、文字を大きく表示します。Ctrl + ; で拡大、Ctrl + - で縮小、Ctrl + 0 で元に戻せます。

本番の前に一度通して流し、すべての発話が正しく認識されるか確かめてください。

商品名を聞き間違えるときは、次のコマンドでヒントの渡し方（`auto`／`list`／`none`）ごとの認識結果を比べ、良いものを `config.py` の `WHISPER_PROMPT_MODE` に設定します。初期値は `auto` です。

```powershell
python compare_prompt.py
```

### 発表で試せる例

| 話す人 | 発話 | 起きること |
|---|---|---|
| お客様 | 瀬戸内海鮮セットのことで電話しました | 対象商品が入る |
| お客様 | 賞味期限はいつまでですか | 「90日」の候補を出す。用件が入る |
| お客様 | 讃岐うどんセットの賞味期限はいつまでですか | 商品が切り替わり「180日」を出す |
| お客様 | みらい入院プランは入院何日目から給付金が出ますか | 保険の候補を出す |
| お客様 | 和牛すき焼きセットを注文したいです | 用件が「注文」になる |
| オペレーター | ご注文を受け付けました | 結果が「注文を受付」になる |
| お客様 | やっぱりやめます | 結果が「お客様の希望で取りやめ」になる |
| お客様 | 瀬戸内海鮮セットの工場は見学できますか | 「候補なし」を出す |

## 仕組み

```text
マイク → 音声区間検出 → 文字起こし ┬→ 質問検出 → 商品の判定 → FAQ検索 → 回答候補
 PyAudio    vad.py    Whisper      └→ 用件・結果の抽出 → フォームへ自動入力
```

商品名は聞き間違えやすいので、ワード・スポッティング（両端点フリー DP）で多少の誤りを許して見つけます。

| ファイル | 役割 | 授業との対応 |
|---|---|---|
| `main.py` | 画面（Tkinter）とスレッドの制御 | - |
| `audio_input.py` | 16kHz・16bit でマイクから録音 | 第15,16回 音声入力（PyAudio） |
| `vad.py` | 発話の始まりと終わりを見つける | 第15,16回 高域強調、フレーム、音声パワー、ゼロ交差率、音声区間検出 |
| `speech_to_text.py` | 音声を文字にする（faster-whisper） | 第15,16回 End-to-End 音声認識、メル尺度 |
| `word_spotting.py` | 誤認識を許してキーワードを見つける | 第19,20回 両端点フリー DP、ワード・スポッティング |
| `faq_search.py` | 質問の検出、商品の判定、FAQ の検索 | 機能① |
| `form_filler.py` | 用件・結果の取り出し | 機能② |
| `call_session.py` | 1通話分の処理と CSV への保存 | - |
| `demo_audio.py` | 録音の再生と読み込み | 第15,16回 音声ファイルの読み込み |
| `record_demo.py` | 発表用の音声を録音 | 第15,16回 音声入力 |
| `compare_prompt.py` | ヒントの渡し方ごとに認識結果を比べる | - |
| `config.py` | しきい値とモデルの設定 | - |
| `data/products.json` | 商品と、その短い呼び方 | - |
| `data/faq.json` | FAQ（質問、キーワード、回答、出典） | - |
| `data/demo_script.json` | 録音で発表するときの台本 | - |

### 調整する場所

`config.py` を変更します。

- 文字起こしが遅い：`WHISPER_MODEL = "base"` にする
- 発話が切れすぎる：`SPEECH_END_MS` を大きくする
- 声に反応しない：`POWER_MARGIN_DB` を小さくする
- 話していないのに反応する：`POWER_MARGIN_DB` を大きくする
- 「候補なし」が多い：`CONFIDENCE_THRESHOLD` を小さくする

FAQ を増やすときは `data/faq.json` に追加します。`keywords` の語が発話に含まれると候補になります。

## 今後の課題

- マイクが1本なので、話す人は手で切り替えています。電話回線の音声を2系統で取れば、自動で分けられます。
- 紙のマニュアルの文字認識（OCR）は作っておらず、FAQ は手で入力したデータを使っています。
- 用件と結果の取り出しは単純なルールなので、言い回しの幅に限界があります。
